### 8. 조용히 틀리는 실패가 더 위험하다 — 0:45

> 과제 4 번, 제공 정보 수신 단계입니다.

> 응답 안에 주문 DB, 운송 DB, FTP 접속정보가 각각 들어 있는데 **세 블록의 키 이름이 전부 똑같습니다.**

### 9. 인코딩이 한 군데가 아니라 세 군데다 — 0:55

> 받는 샘플 데이터가 **EUC-KR** 입니다. Base64 를 풀고 UTF-8 로 읽으면 한글이 깨지고 그 상태로 DB 와 파일까지 전파됩니다.
> 올리는 영수증 **내용**도 EUC-KR 입니다. 원본 XML 인코딩을 계승했습니다.
> 그런데 **파일 이름은 UTF-8** 입니다. FTP 는 명령을 주고받는 제어 채널과 데이터 채널이 따로 있고 파일 이름은 제어 채널로 나갑니다. commons-net 기본값이 ISO-8859-1 이라 그냥 두면 한글이 **물음표로 바뀌어 올라가고 예외도 안 납니다.** 서버가 UTF8 을 지원한다고 선언해서 맞췄습니다.
> 전송 모드는 바이너리 고정입니다. 텍스트 모드는 줄바꿈을 바꿔 포맷이 틀어집니다.
> 그리고 업로드 후 파일명과 크기를 다시 조회해 확인합니다. 인코딩이 깨졌거나 파일이 잘려도 예외 없이 성공으로 보고되기 때문입니다.

### 10. DB 와 FTP 를 함께 성공시키기 — 2:00 ★

> 과제 3.1 의 세 번째 항목입니다. 두 개가 모두 처리되었을 때 결과를 반환하라.
> 문제는 FTP 가 DB 트랜잭션에 못 들어온다는 겁니다. **파일에는 롤백이 없습니다.**
>
> *(멈춤)*
>
> 그래서 처음엔 교과서대로 짰습니다. DB 에 넣되 커밋은 미루고, 파일은 임시 이름으로 올리고, 다 되면 DB 커밋 후 이름을 바꿉니다. 틀어지면 임시 파일을 지웁니다.
>
> 그런데 돌려보니 **서버가 이름 바꾸기를 거부했습니다.** 451 이 떨어졌습니다. 지우기라도 되나 했더니 550 으로 거부했습니다. 오라클도 DELETE 권한이 없었습니다.
> 지원자 여럿이 같은 테이블·같은 폴더를 쓰니 서로 못 건드리게 막아둔 구성으로 보입니다. 즉 **이 환경은 한 번 쓰면 되돌릴 수 없습니다.**
>
> 여기서 판단을 바꿨습니다. 되돌릴 수 없는 환경에서는 **되돌리는 로직을 정교하게 짜는 게 답이 아니라, 되돌릴 게 안 생기게 만드는 게 답**이라고 봤습니다.
> 준비 단계에서는 서버에 아무것도 쓰지 않습니다. 확정 시점에 최종 이름으로 딱 한 번 올립니다. **임시 이름 개념 자체가 사라졌습니다.**
> 순서도 정했습니다. DB 를 먼저 확정하고 FTP 를 나중에. 뒤집으면 이미 배포된 영수증을 회수해야 합니다.
>
> 마지막으로, **DB 는 커밋됐는데 파일이 실패한 경우**입니다. 실패라고 응답하면 상대가 다시 보내고 **이미 들어간 63건이 한 번 더 들어갑니다.** 그래서 실패가 아니라 "사람이 파일 하나만 올리면 된다"는 결과로 따로 보고합니다.

**질문 대비** — 2PC 는 FTP 가 XA 리소스가 아니라 선택지가 아니었다 / 아웃박스는 "둘 다 됐을 때 반환"이라는 요구와 최종적 일관성이 안 맞았다.

### 11. 5분 주기가 만드는 함정 셋 — 0:50

> **첫째**, 앞 회차가 5분을 넘기면 다음 회차가 겹쳐 돕니다. 같은 주문이 두 번 갑니다. Redis 로 한 번에 하나만 돌게 막았습니다. **락 유효시간은 4분**으로 주기 5분보다 짧게 뒀습니다. 길면 프로세스가 죽어 락을 반납 못 했을 때 그 시간 동안 배치가 통째로 멈춥니다.
> **둘째**, 걸러낸 행은 상태가 안 바뀌어 다시 조회하면 또 나옵니다. "0건 나올 때까지" 돌면 무한 루프입니다. 그래서 **마지막으로 읽은 번호부터** 읽습니다. 청크 100건, 한 실행 최대 50청크로 제한했습니다. 이 상한이 있어야 락 유효시간을 안 넘긴다고 말할 수 있습니다.
> **셋째**, 운송 테이블 적재와 상태 변경을 같은 트랜잭션에 묶었습니다. 나누면 "보냈는데 안 보낸 걸로 남는" 상태가 생깁니다. 두 테이블이 같은 계정인 걸 먼저 확인하고 정했습니다.
> 아래 하나만 — **락이 잡혀 있는 것**과 **락을 확인조차 못 하는 것**을 다른 코드로 나눴습니다. 하나로 묶으면 Redis 장애가 정상처럼 보입니다.

### 12. 로그만 보고 누구한테 연락할지 알 수 있게 — 0:55

> 과제 3.3 은 로그와 예외 처리 두 가지입니다.
> 애플리케이션 로그와 **인터페이스 실행 이력을 분리**했습니다. 한 줄이 한 구간입니다. 요청 하나에 추적 아이디 하나가 붙습니다.
> 열을 고정폭으로 맞춘 건 **눈으로 세로로 훑기 위해서**입니다. 키=값 형식은 파싱은 쉬워도 사람이 못 읽습니다. 이름과 주소는 남기지 않습니다.
> 에러 코드는 구간별로 대역을 나눴습니다. **코드만 보고 누구한테 연락할지** 알게 하려는 겁니다.
> 그리고 코드마다 **다시 하면 될 일인가**를 같이 붙여놨습니다. 호출부가 매번 판단하면 검증 실패를 무한 재시도하는 사고가 납니다.
> 재미있는 건 **같은 FTP 업로드 실패라도 준비 단계면 재시도해도 되고 확정 단계면 절대 안 된다**는 겁니다. 그래서 코드를 둘로 나눴습니다.

### 13. 안 쓴 것에 이유가 있다 — 0:40

> 웹 스타터가 들어간 건 화면 때문이 아니라 **시나리오 1 의 수신부 자체가 REST** 이기 때문입니다.
> 오른쪽이 일부러 안 쓴 것들인데 이쪽이 설명할 게 더 많습니다. JPA 를 안 쓴 이유는 앞과 같습니다. 엔티티를 만드는 순간 우리가 주문을 가진 것처럼 보입니다. 그리고 스키마가 불변 조건인데 **DDL 자동 생성 여지가 있는 기능은 그 자체로 위험 요소**입니다.

### 14. AI 를 어떻게 썼나 — 1:10

> 과제 5.1 에 명시적으로 요구된 항목이라 구체적으로 말씀드리겠습니다. **도구를 쓴 게 아니라 작업 방식을 정해 놓고** 들어갔습니다.
> 역할을 셋으로 나눴습니다. 무엇을 만들지·무엇을 포기할지는 제가 정합니다. 정리하고 써 내는 건 Claude 에 맡깁니다. 돌려 보고 확인하는 건 다시 제가 합니다. 빌드·git·원격 DB·FTP 접속은 전부 직접 했습니다.
> 이번 과제에서 실제로 한 것 둘만 말씀드리면 —
> 첫째, **프로젝트 디렉터리를 MCP 로 물려서** 파일 작업을 맡겼습니다. 채팅창에서 코드를 복사해 붙이는 방식이 아닙니다.
> 둘째, **대화를 그때그때 설계 결정으로 옮겨 적었습니다.** 26건인데 전부 근거가 같이 있고, 그중 하나는 제가 세웠다가 스스로 철회했습니다. 배치 중복 처리 정책인데, 처음엔 "키가 충돌하면 이미 처리된 걸로 보고 넘어가자"였습니다. 그런데 번호를 우리가 직접 매기니까 충돌은 **넘어갈 일이 아니라 번호 매기기가 망가진 신호**라는 걸 깨닫고 뒤집었습니다.
> 마지막 줄은 평소 방식입니다. **규모가 커지면** 웹 Claude 를 설계 헤드로 두고 Claude Code CLI 에 실행을 위임하는 구성을 씁니다. **이번 과제는** 단일 세션으로 충분해 쓰지 않았습니다.

> ⚠️ "평소에는" 을 **또렷하게 끊어서** 말할 것. 앞과 붙여 읽으면 이번 과제에 쓴 것처럼 들린다.

## 3. 예상 질문

| 질문 | 답의 핵심 |
|---|---|
| 2PC 를 왜 안 썼나 | FTP 는 XA 리소스가 아니다. 선택지가 아니었다 |
| 트랜잭셔널 아웃박스는 | "둘 다 됐을 때 반환"이라 응답 시점에 전송이 끝나야 한다. 최종적 일관성과 안 맞았다 |
| 왜 `JdbcTemplate` 인가 | 스키마가 불변 조건이다. ORM 은 도메인을 소유한다는 잘못된 신호를 준다 |
| 실시간은 부분 처리, 배치는 전건 스킵 — 왜 다른가 | 실시간엔 **고쳐 줄 호출자**가 있고 배치엔 없다. 배치에서 전체 거부하면 잘못된 1건이 정상 99건을 영구히 막는다 |
| Redis 가 죽으면 | 락을 확인할 수 없으면 **락 없이 진행하지 않는다.** 되돌릴 수 없는 환경에서 중복 전송이 최악이다 |
| 채번 공간이 26,000 개뿐인데 | 유한함을 문서에 기록했고 소진 시 전용 코드로 즉시 실패시킨다 |
| 왜 Spring Batch 를 안 썼나 | 청크 반복이 20줄 남짓이다. 프레임워크가 문제보다 커진다 |
| 실제 DB 로 통합 테스트를 왜 안 했나 | append-only 공유 환경이라 실패 경로를 재현하면 되돌릴 수 없는 행이 남는다. "아직 커밋하지 않았다"는 실물로 관측이 안 된다 |
| AI 가 짠 코드를 다 이해하나 | 설계 결정 26건이 근거와 함께 있고 그중 하나는 내가 뒤집었다. 이해 못 하면 뒤집을 수 없다 |
| 개인정보는 | 이력 로그에 이름·주소를 남기지 않는다. 검증 위반 기록도 값이 아니라 규칙·필드·위치만 담는다 |
